# EVRIKA CRM v1.0 — сборка для тестирования

Два приложения Windows (Electron), единый сервер Node.js + Express, Socket.IO и настоящая локальная PostgreSQL. База не SQLite, не JSON и не облако. PostgreSQL устанавливается как отдельная служба Windows на ПК администратора. Рабочие места подключаются только к HTTP(S)-серверу CRM, а не к PostgreSQL. Использован прямой драйвер pg вместо Sequelize, чтобы явно контролировать транзакции и блокировки строк.

## 1. Установка на компьютере администратора

Требуется Windows 10/11 x64, Node.js 22 или 24 LTS (https://nodejs.org/), PostgreSQL для Windows (https://www.postgresql.org/download/windows/). При установке PostgreSQL включите Database Server и Command Line Tools; pgAdmin удобен, но необязателен. Запомните пароль пользователя postgres и порт (обычно 5432). Не открывайте порт PostgreSQL в локальную сеть: доступ нужен только с 127.0.0.1. Если PostgreSQL уже установлен, переустанавливать его не надо.

Распакуйте ZIP в постоянную папку, например C:\EVRIKA-CRM. Не храните рабочую БД или пароль в общей папке; ограничьте доступ к каталогу проекта, .env, backups и логам доверенными администраторами. Откройте PowerShell в распакованной папке, выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

Скрипт найдёт PostgreSQL, спросит порт и пароль postgres, создаст роль `evrika_app` и БД `evrika_crm`, сгенерирует случайные пароль БД и JWT-секрет, запишет `.env`, установит npm-зависимости, создаст таблицы и первого администратора (логин и пароль задаются при установке, пароль минимум 12 символов). Для npm нужен интернет. Если роль или БД уже существует, скрипт остановится, чтобы ничего не перезаписать. Если `.env` уже существует, скрипт сохранит его настройки и не изменит пароль существующего администратора. При ошибке установки не удаляйте существующую БД: проверьте .env и лог ошибки.

В случае ручной настройки: скопируйте `.env.example` в `.env`, создайте роль и базу через pgAdmin (отдельными запросами):

```sql
CREATE ROLE evrika_app LOGIN PASSWORD 'ваш_случайный_пароль';
CREATE DATABASE evrika_crm OWNER evrika_app ENCODING 'UTF8';
```

Затем заполните DB_PASSWORD, JWT_SECRET (случайная строка не менее 32 символов) и PG_BIN в .env. Выполните `npm.cmd install`, задайте `INIT_ADMIN_LOGIN` и `INIT_ADMIN_PASSWORD` через переменные окружения (не сохраняйте пароль в .env), выполните `npm.cmd run setup`, удалите временные переменные. `server/schema.sql` содержит SQL схемы; `setup` выполняет его в транзакции. Не нужно отдельно импортировать SQL, если setup уже прошёл.

## 2. Запуск и проверка

В первом терминале:

```powershell
npm.cmd start
```

Проверьте http://localhost:3000/api/health — должен быть JSON с `ok:true` и `database:PostgreSQL`. Откройте http://localhost:3000/ в браузере или во втором терминале запустите:

```powershell
npm.cmd run admin
```

Войдите под администратором, которого создали при настройке. Добавьте двух сотрудников, используя вкладку «Сотрудники». Для быстрого теста можно использовать два независимых браузера (или обычное и приватное окно) по тому же адресу. Для Electron-сотрудника используйте `npm.cmd run employee`, затем введите адрес сервера (на том же ПК — http://127.0.0.1:3000).

В Electron по умолчанию полноэкранный режим. F11 или Esc — выйти из него; настройки позволяют переключить тему, свернуть окно и изменить адрес. Для выхода Alt+F4. Тема сохраняется на данном компьютере отдельно для логина. В Windows уведомления зависят от системных настроек; в браузере звуки/уведомления могут быть заблокированы его политиками.

## 3. Сеть и автозапуск

Для первоначального теста используется HTTP внутри доверенной локальной сети. Не вводите реальные персональные данные до настройки HTTPS, проверки прав доступа и резервного копирования. Для теста на одном компьютере можно временно выставить `HOST=127.0.0.1` в .env. Для сети вернуть `HOST=0.0.0.0`.

Узнайте IPv4 администратора командой `ipconfig`. Например, `192.168.1.100` (это пример, используйте свой IP). Желательно зарезервировать IP в DHCP роутера. На Windows-профиле сети «Частная» разрешите входящий TCP 3000 только из локальной подсети. Для автоматической настройки откройте PowerShell от имени администратора, остановите ручной сервер Ctrl+C, затем:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\autostart.ps1
```

Скрипт создаёт задачу планировщика при старте Windows под указанной учётной записью Windows с ограниченными правами, с перезапусками при сбое, и правило брандмауэра. Нужен реальный пароль учётной записи, не PIN. Указанная учётная запись должна иметь доступ к проекту, .env, backups, Node.js и pg_dump. PostgreSQL должен запускаться как служба Windows. Если политика компании запрещает сохранение пароля в планировщике, настройте отдельную служебную учётную запись с IT. При изменении PORT вручную скорректируйте правило брандмауэра. Для отмены — `scripts\stop-autostart.ps1` с правами администратора. База при этом не удаляется.

Сотрудникам в Electron введите `http://ВАШ_IP:3000`. Интернет для штатной локальной работы после установки не нужен. При отключении ПК администратора система недоступна.

## 4. Сборка приложений Windows

На компьютере разработчика/администратора, после npm install:

```powershell
npm.cmd run build:admin
npm.cmd run build:employee
```

Или `scripts\build-windows.cmd`. Установщики ожидаются в `dist\admin` и `dist\employee`. Оба имеют фирменную ICO-иконку, отдельные имена и ярлыки. Установщик Admin содержит desktop-клиент, а сервер и БД на ПК администратора устанавливаются отдельно по шагам 1–3. Employee не требует Node.js/PostgreSQL. Сборки не подписаны, Windows SmartScreen может предупредить об неизвестном издателе; не отключайте защиту Windows целиком. Подпись сертификатом — отдельный этап.

## 5. Проверка функционала

1. Админ создаёт личный заказ и общий заказ. Личный видит только назначенный сотрудник, общий — все. Новые задачи выше остальных, внутри группы — по дате создания от новых к старым.
2. Два сотрудника одновременно нажимают «Взять в работу»: один выигрывает, второй получает отказ. Общая карточка остаётся у всех, редактирование доступно только владельцу и администратору.
3. Сотрудник добавляет два вида комментариев. Они появляются у всех пользователей, которым доступна задача. История содержит имя и время автора.
4. Выберите результат и дату. «Состоялась» и «Сорвалась» → завершённые, «Перенеслась» → в работе. Завершённые сотрудник не редактирует, администратор может исправить результат.
5. Админ в «Этапы» открывает сотрудника: четыре горизонтальных блока по каждой задаче. В «Клиенты» доступны те же карточки, в том числе уволенных сотрудников, поиск и удаление.
6. Админ забирает общий заказ: он освобождается. Забирает личный: он появляется в «Ожидают назначения». Передача меняет владельца, история сохраняется. Тип заказа не меняется.
7. Удалите сотрудника: аккаунт деактивируется, задачи и их статус/владелец сохраняются, автоматического переназначения нет. Если надо, админ назначает другого из «Клиенты».
8. Откройте Excel-экспорт, журнал действий, семь тем, проверьте звук и Windows-уведомление. Отключите сеть и подключите обратно, проверьте синхронизацию.
9. Перезапустите сервер: данные должны сохраниться. Проверьте копию через `npm.cmd run backup`.

## 6. Резервные копии и база

Настоящая PostgreSQL хранит данные в своём каталоге данных, не внутри исходников. Таблицы `users`, `clients`, `tasks`, `comments`, `audit` находятся в БД `evrika_crm`, в схеме `public`. Открыть через pgAdmin: Servers → PostgreSQL → Databases → evrika_crm → Schemas → public → Tables. Данные не отправляются в облако.

Сервер при старте и далее ежечасно проверяет необходимость создания копии; если последней копии нет или ей больше 24 часов, выполняет `pg_dump -Fc`. Копии в `backups`, по умолчанию 30 дней. Ручная копия: `npm.cmd run backup`. Настройте PG_BIN на каталог bin установленной PostgreSQL. Храните дополнительные зашифрованные копии на другом носителе: копия на том же диске не защитит от его отказа. Проверяйте восстановление отдельно.

Восстанавливайте сначала в НОВУЮ тестовую базу, не перезаписывайте рабочую. Например, через pgAdmin создайте `evrika_restore_test` с владельцем evrika_app, затем в PowerShell (подставьте путь к pg_restore и копии):

```powershell
& 'C:\Program Files\PostgreSQL\17\bin\pg_restore.exe' -h 127.0.0.1 -p 5432 -U evrika_app -d evrika_restore_test --no-owner --exit-on-error 'C:\EVRIKA-CRM\backups\evrika-ВАША-ДАТА.dump'
```

## 7. HTTPS и будущий Cloudflare Tunnel

Не публикуйте тестовый HTTP сервер в интернет. Сервер поддерживает TLS через `TLS_CERT` и `TLS_KEY` (PEM), нужен сертификат, доверенный Windows и браузерами и соответствующий адресу сервера. Не отключайте проверку сертификатов. Для Cloudflare Tunnel в будущем отдельно настроить DNS, защищённый доступ, серверную привязку, заголовки прокси и тест безопасности. В текущем архиве Tunnel не настроен.

## 8. Состояние тестирования

Это исходная сборка для испытаний, не готовый проверенный production-релиз. Проверены синтаксис JS и 3 автономных теста правил. Установка npm, запуск реального PostgreSQL, Socket.IO между компьютерами, планировщик, резервное копирование, Excel и сборка EXE требуют проверки на Windows (в среде подготовки нет PostgreSQL и доступ к npm registry недоступен). В архиве нет node_modules, PostgreSQL-инсталлятора, .env с секретами, готовых EXE и реальных данных.

Принятые технические решения: pg вместо Sequelize; удаление аккаунтов и заказов логическое для сохранения истории; каждый созданный заказ получает отдельную клиентскую запись (без автоматического объединения одинаковых телефонов); автокопия ежедневно, 30 дней; в журнале интерфейса последние 500 событий (база хранит все); сервер и Admin Electron независимы, поэтому закрытие окна не останавливает сервер. Доступ к комментариям и личным заказам контролируется на сервере. Тема по умолчанию Black & Gold.
